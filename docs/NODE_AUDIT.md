# Audit Node Afivision Builder

**Tanggal audit:** 2026-10-24  
**Sumber inventaris:** `engine/node_catalog.py` → `NODE_BLUEPRINTS` (83 node).  
**Tujuan:** inventaris menyeluruh katalog, indeks test langsung, dan jejak kode runtime untuk tiap node. Ini audit bukti statis; bukan klaim uji runtime setiap node.

## Ringkasan eksekutif

- Inventaris berisi **83 node** dalam **8 kategori**.
- Hasil cakupan langsung: **42 node** dirujuk unit+E2E, **25** unit saja, **11** E2E saja, **5** tanpa bukti test langsung. Ini indeks keberadaan test, bukan nilai kualitas atau kelulusan node.
- **Tidak ada node yang aku cap “kacau/rusak” hanya dari hasil audit ini.** Tidak ada bukti cukup untuk vonis itu; node tanpa test diberi status “belum terbukti”, bukan dianggap error.
- Unit test penuh peta awal: **229 passed** (6 deprecation warnings). Setelah penambahan 8 uji langsung untuk logic gates dan perbaikan `debounce`, `pytest tests/unit -q --tb=short`: **237 passed** (6 warnings); dua file unit Phase 5 terkait: **17 passed**.
- `npm run test:e2e`: run awal 47/47 gagal sebelum interaksi aplikasi karena target tidak tersedia (`ERR_CONNECTION_REFUSED`), jadi suite penuh belum terverifikasi. Setelah app sementara tersedia, sampel Phase 5 dan Phase 3 lulus: `npx e2e run tests/phase5_sinks_and_aggregation.e2e.ts` **PASS 1/1** (12 screenshot, 12,47 dtk, 10,9k token) dan `npx e2e run tests/advanced_logic_and_kinematics.e2e.ts` **PASS 1/1** (11 screenshot, 11,05 dtk, 10,0k token). Keduanya menguji UI/inspector, bukan runtime node penuh atau kamera/PTZ nyata.
- Tidak ada kamera, rekaman lapangan, ERP nyata, atau performa multi-camera yang diuji pada audit ini. Graphify tidak tersedia (`graphify-out/GRAPH_REPORT.md` tidak ada).

## Cara membaca status

- **Cakupan unit + E2E:** test dengan rujukan node ditemukan pada dua jenis file. Karena suite E2E gagal di setup, ini belum verifikasi E2E yang sukses.
- **Bukti unit saja:** ada test unit terdeteksi, tetapi bukti E2E/lapangan tidak lengkap.
- **E2E saja:** hanya test E2E yang ditemukan; jalur runtime belum ada bukti unit langsung.
- **Belum terbukti:** tidak ditemukan test yang secara langsung menyebut node ID/nama katalog. Perlu cek implementasi dan tambah test.
- Pemetaan test bersifat mekanis dengan batas kata untuk ID/nama dalam berkas test. Test bersama bisa menghasilkan false positive/negatif; daftar ini indeks bukti, bukan evaluasi kualitas test secara mendalam.
- “Kacau” hanya boleh dipakai bila bug bisa direproduksi atau ditemukan cacat implementasi spesifik. Tidak ada temuan seperti itu yang terverifikasi pada pass ini.

## Temuan tingkat sistem dan prioritas

### P0 — bereskan dulu sebelum klaim matang/siap produksi

1. **E2E suite penuh belum terverifikasi.** Run awal 47 test tidak tersambung ke app (`ERR_CONNECTION_REFUSED`); setelah server sementara tersedia, sampel Phase 3 dan Phase 5 lulus. Jalankan seluruh suite dengan app/data test terisolasi sebelum menjadikannya release gate.
2. **Operasi multi-camera masih prototipe.** Dokumen `docs/TASK_LIST.md` mencatat satu runner aktif, belum ada registrasi/deployment terisolasi per kamera, restart/recovery, dan uji beban 8 stream.
3. **Zona dan timer belum lolos data lapangan.** Belum ada replay anotasi nyata; persistensi/recovery sesi dan batas ketidakpastian saat frame terputus masih terbuka.
4. **Keluaran eksternal belum andal untuk operasi nyata.** ERP durable, idempotensi, retry/recovery setelah restart dan verifikasi penerimaan ERP masih belum tersedia/terbukti.
5. **Model task-specific belum divalidasi.** Kelas/model metadata bukan bukti mampu mengenali objek target; evaluasi rekaman beranotasi tetap wajib.

### P1 — tingkatkan konsistensi node

1. Tambahkan kontrak input/output terstruktur dan validasi config seragam di API, runner serial, runner threaded, serta ekspor.
2. **FIXED (selector UI):** Dua sampel E2E memakai `.hub-open-workflow-btn` agar tidak bergantung pada bahasa UI; Phase 5 dan Phase 3 lulus dalam sesi terisolasi.
3. **FIXED (runtime gate):** `debounce` sebelumnya tidak mencatat transisi awal sinyal high dengan benar, sehingga sinyal low pertama tidak mereset waktu; perbaikannya kini dilindungi test transisi dan batas waktu.
4. Tambahkan test parametrik per node: konfigurasi valid/invalid, frame kosong, ukuran/format berbeda, bypass/disabled, error dependency, serta nilai batas. Audit kontrak `and_or_logic` khususnya: test saat ini hanya membuktikan sinyal deteksi + boolean konfigurasi, belum komposisi beberapa input gate.
5. Tautkan katalog node → handler runtime → unit tests → E2E dalam satu manifest otomatis agar node yang hanya tampil di UI tidak tampak “selesai”.
6. Pisahkan status “tested synthetically”, “E2E UI”, “real model/video”, dan “production/pilot” di UI/docs.
7. Rapikan deprecation warning FastAPI lifespan; bukan blocker fungsional yang terbukti, tapi warning menambah noise.

## Rencana audit lanjutan

1. Bangun app pada konfigurasi test terisolasi dan perbaiki/ulang suite E2E (jangan gunakan workflow produksi pengguna).
2. Pecah 83 node per kategori; audit trace lengkap library → inspector → validation → serial/threaded execution → output packet → export.
3. Prioritaskan semua node **Belum terbukti** dan node yang berdampak pada rilis awal (camera/input, detector/tracker, zone, timer/event, screenshot, sinks).
4. Jalankan tes metamorfik dan replay video beranotasi; laporkan precision/recall, latensi, dropped frames, memory, dan robustness.
5. Setelah bukti per node ada, revisi status. Jangan mengubah kode/model atau workflow pengguna tanpa persetujuan scope terpisah.
